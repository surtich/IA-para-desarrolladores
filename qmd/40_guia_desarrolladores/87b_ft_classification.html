Ajuste fino en un modelo de clasificación

Introducción

En esta sección, aprenderá a realizar el ajuste fino (fine-tuning) de un modelo de lenguaje preentrenado y ya ajustado para una tarea de clasificación concreta. Se reentrenarán los pesos para adaptarlo a la tarea de clasificación de su dataset. El objetivo es tomar un modelo que ya posee una base sólida de comprensión del idioma y adaptarlo específicamente a su propio conjunto de datos para resolver una tarea de clasificación concreta.

Ejemplo de entrenamiento

Línea base

Antes de modificar los pesos de cualquier red neuronal, es una práctica fundamental comprobar cómo se comporta el modelo preentrenado “de fábrica” con sus datos. Esto marcará nuestra línea base (baseline), permitiéndonos evaluar con métricas reales si el entrenamiento posterior realmente aporta valor o mejora el rendimiento del modelo.

Para establecer esta línea base utilizaremos una técnica llamada clasificación zero-shot. Como su nombre indica, zero-shot (cero disparos/ejemplos) significa que el modelo intentará clasificar el texto basándose únicamente en su conocimiento previo del mundo, sin haber visto jamás un solo ejemplo de entrenamiento de nuestro dataset.

Definimos primero el identificador del modelo que utilizaremos desde el Hub de Hugging Face. En este caso, un modelo basado en RoBERTa optimizado para tareas de inferencia en español:

Haz clic para ver el código

A continuación, preparamos el entorno cargando nuestro conjunto de datos estructurado desde el disco. Aprovecharemos para construir dos diccionarios de mapeo bidireccional (label2id e id2label). Al analizar la salida de la celda anterior, podemos observar que la arquitectura del modelo se divide estructuralmente en tres bloques esenciales:

  • 1. Capa de Entrada: roberta.embeddings Es la encargada de transformar el texto en vectores matemáticos que el modelo pueda procesar.

    • word_embeddings (50265, 768): El vocabulario del modelo tiene un tamaño de 50.265 tokens únicos. Cada uno de estos tokens se representa inicialmente como un vector continuo de 768 dimensiones (la dimensión oculta estándar de los modelos base).
    • position_embeddings (514, 768): Como los Transformers procesan todas las palabras a la vez, necesitan saber el orden de los elementos. Este componente mapea la posición física de cada palabra en el texto. Soporta textos de hasta 512 tokens de longitud máxima (más 2 tokens especiales de control).
    • LayerNorm y Dropout: Capas de normalización y regularización para dar estabilidad matemática al inicio del flujo y evitar el sobreajuste (overfitting).

  • 2. El Cuerpo del Modelo: roberta.encoder Este es el motor principal del modelo, encargado de extraer el significado y el contexto profundo del texto.

    • 12 Bloques Idénticos (0-11): Contiene una lista modular (ModuleList) de 12 capas consecutivas de tipo RobertaLayer. El texto pasa secuencialmente a través de cada una de ellas. Cada una de estas 12 capas se compone internamente de:
      • Mecanismo de Atención (RobertaAttention): Calcula la relación de cada palabra con todas las demás del texto usando proyecciones lineales llamadas Query, Key y Value (todas manteniendo las 768 dimensiones). Esto le permite entender, por ejemplo, a qué se refiere un pronombre.
      • Capa Intermedia (RobertaIntermediate): Una red neuronal densa (Feed-Forward) que expande temporalmente las 768 dimensiones hasta 3072 dimensiones para realizar cálculos complejos y extraer patrones abstractos, aplicando una función de activación no lineal GELU.
      • Capa de Salida (RobertaOutput): Vuelve a comprimir las dimensiones de 3072 a 768 y las normaliza para inyectarlas en la siguiente capa del Transformer.

  • 3. La Cabeza de Clasificación: classifier Esta es la extensión añadida al final del modelo base para resolver tareas de clasificación.

    • dense (768 -> 768): Una capa lineal intermedia.
    • out_proj (768 -> 3): Esta es la capa final de salida (la matriz de proyección). Recibe las 768 características complejas del texto y las reduce a 3 salidas (Logits).

def contar_parametros(modelo):
    # Sumamos los elementos (numel) de cada matriz de pesos en el modelo
    total_params = sum(p.numel() for p in modelo.parameters())
    
    # Sumamos solo aquellos que tienen activado el gradiente (se van a entrenar)
    trainable_params = sum(p.numel() for p in modelo.parameters() if p.requires_grad)
    
    print(f"========================================")
    print(f" Parámetros Totales:    {total_params:,}")
    print(f" Parámetros Entrenables: {trainable_params:,}")
    print(f" Parámetros Congelados:  {total_params - trainable_params:,}")
    print(f"========================================")

Asimismo, medimos el tamaño físico que ocuparán los pesos del modelo dentro de la memoria RAM o la memoria de vídeo (VRAM) de nuestro acelerador de hardware para asegurar la viabilidad de la ejecución:

Haz clic para ver el código 
def calcular_tamano_memoria(modelo):
    # 1. Calcular los bytes que ocupan los parámetros del modelo
    param_bytes = sum(p.numel() * p.element_size() for p in modelo.parameters())
    
    # 2. Calcular los bytes que ocupan los buffers (parámetros fijos no entrenables)
    buffer_bytes = sum(b.numel() * b.element_size() for b in modelo.buffers())
    
    # 3. Sumar todo y convertir a Megabytes
    total_bytes = param_bytes + buffer_bytes
    total_mb = total_bytes / (1024 ** 2)
    
    print(f"========================================")
    print(f" Memoria en disco/RAM: {total_mb:.2f} MB")
    print(f"========================================")

# Conversión a arreglos de NumPy para una comparación vectorizada

Justificación de la línea base

Asumiendo un escenario donde la exactitud obtenida por nuestro clasificador zero-shot es de 59%, este porcentaje se convertirá oficialmente en nuestra línea base a batir.

Recordemos que para establecer si una línea base es sólida, podemos compararla contra estrategias básicas de control:

    1. Predicción Aleatoria: Produciría una exactitud cercana al 50% en tareas binarias perfectamente balanceadas.
    1. Clase Mayoritaria: Predecir siempre la categoría más común del dataset, obteniendo una exactitud proporcional a la distribución de dicha clase.

Dado que nuestro modelo zero-shot supera el comportamiento puramente aleatorio, su 59% representa un punto de partida competitivo que intentaremos superar mediante el ajuste fino supervisado.

Preparación de datos y Fine-Tuning Supervisado

Importamos las librerías necesarias para construir nuestro flujo de entrenamiento supervisado:

Haz clic para ver el código 
from transformers import AutoModelForSequenceClassification
from transformers import AutoTokenizer
from transformers import TrainingArguments, Trainer
from transformers import DataCollatorWithPadding
from datasets import load_from_disk
import numpy as np
import evaluate

Instanciamos el tokenizador correspondiente a nuestra arquitectura de modelo base para garantizar que los textos se dividan en subpalabras utilizando exactamente las mismas reglas y diccionarios con los que el modelo fue originalmente concebido:

Haz clic para ver el código 
tokenizer = AutoTokenizer.from_pretrained(model_id)

Definimos una función de preprocesamiento encargada de mapear el tokenizador sobre los textos, aplicando un truncamiento estricto (truncation=True) para recortar cualquier texto que exceda el límite máximo de tokens del modelo:

Haz clic para ver el código 
def preprocess_function(examples):
    # Aplicar el tokenizador a la columna 'text', 
    # truncando las secuencias que sean demasiado largas
    return tokenizer(examples["text"], truncation=True)

# Cargar el conjunto de datos guardado desde el paso de preparación de datos
ds = load_from_disk(base_path / "data/dataset_encoded")

# Aplicar la función de preprocesamiento a todo el 
# conjunto de datos usando map para mayor eficiencia
tokenized_dataset = ds.map(preprocess_function, batched=True)

Creamos un colador de datos (Data Collator). Su función será empaquetar los ejemplos en batches durante el entrenamiento y aplicar un relleno dinámico (dynamic padding), asegurando que todos los textos dentro de un mismo lote tengan exactamente la misma longitud que el texto más largo de ese lote particular, optimizando el uso de memoria.

Haz clic para ver el código 
data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

Cargamos el modelo especializado en clasificación de secuencias. Dado que el modelo original operaba con 3 clases y nuestro problema actual requiere únicamente 2 clases, especificamos num_labels=2 y suministramos nuestros diccionarios de mapeo personalizados. El parámetro ignore_mismatched_sizes=True es crítico aquí, ya que le advierte al framework que descarte la cabeza de clasificación antigua de 3 salidas e inicialice una nueva capa lineal de \(768 \times 2\) con valores aleatorios lista para ser entrenada:

Haz clic para ver el código 
model = AutoModelForSequenceClassification.from_pretrained(
    model_id, 
    num_labels=2, 
    id2label=id2label, 
    label2id=label2id, 
    ignore_mismatched_sizes=True
)

Definimos la función auxiliar que invocará el evaluador del Trainer al final de cada ciclo para transformar las salidas continuas (logits) de la red en predicciones discretas mediante un argmax:

Haz clic para ver el código 
accuracy = evaluate.load("accuracy")

def compute_metrics(eval_pred):
    # El Trainer proporciona las predicciones y las etiquetas reales durante la evaluación
    predictions, labels = eval_pred
    # Obtener el ID de la clase predicha (la que tiene la probabilidad más alta)
    predictions = np.argmax(predictions, axis=1)
    # Utilizar la métrica de exactitud cargada para comparar las predicciones con las etiquetas reales
    return accuracy.compute(predictions=predictions, references=labels)

Ejemplo entrenando sólo la cabeza (head)

A dife,rencia del Full Fine-Tuning donde alteramos la totalidad de las capas del Transformer, existe una estrategia alternativa y computacionalmente eficiente llamada extracción de características o congelamiento de pesos (weights freezing).

En esta modalidad, asumimos que el cuerpo del modelo base ya comprende perfectamente la estructura gramatical y semántica del lenguaje español. Por ende, congelamos todos sus bloques internos de atención y procesamiento para que permanezcan inalterados, y concentramos el 100% del entrenamiento de manera exclusiva en adaptar la nueva cabeza de clasificación lineal final hacia nuestras etiquetas particulares.

Para implementar este enfoque, volvemos a instanciar el modelo de origen desde el Hub:

Haz clic para ver el código 
model_head_only = AutoModelForSequenceClassification.from_pretrained(
    model_id, 
    num_labels=2, 
    id2label=id2label, 
    label2id=label2id, 
    ignore_mismatched_sizes=True
)

Iteramos sobre todos los parámetros de la estructura base del modelo (base_model) y desactivamos el cálculo de gradientes fijando la propiedad requires_grad en False. Esto congelará las 12 capas del codificador y sus capas de embeddings:

Haz clic para ver el código 
for param in model_head_only.base_model.parameters():
    param.requires_grad = False

Invocamos nuestra función auxiliar previamente definida para auditar el estado del modelo y confirmar que el cuerpo se encuentra bloqueado pero la cabeza se mantiene editable:
